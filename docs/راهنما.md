# VoidForge — راهنمای کامل و گزارش ساخت

**نسخه:** `1.0.0`  
**تاریخ:** ۲۶ نوامبر ۲۰۲۶  
**مسیر پروژه:** `~/VoidForge`  
**لایسنس:** MIT  
**نوع برنامه:** رابط ترمینالی تعاملی (TUI) برای ساخت و مدیریت بستههای Void Linux

> برنامه VoidForge یک «کارگاه بسته سازی Void Linux» در ترمینال است. این برنامه با `xbps-src` واقعی کار میکند،
> از الگوها، پچها، وابستگیها، مخزن Git و لاگهای ساخت بهصورت حقیقی خوانده و مینویسد و هیچ سرور وب،
> مرورگر، localhost، Tauri، React یا Viteای در آن باقی نمانده است.

## 1. اجرای سریع

سادهترین راه اجرا:

```bash
cd ~/VoidForge
cargo run
```

برای ساخت نسخهٔ بهینهشده و اجرای مستقیم:

```bash
cd ~/VoidForge
cargo build --release
./target/release/voidforge
```

برای بررسی سلامت پروژه:

```bash
cargo fmt --all
cargo check --all-targets
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

پس از اجرا، صفحهٔ **Dashboard** با اطلاعات واقعی میزبان، ابزارها و منابع سیستم نمایش داده میشود.
برای خروج از برنامه کلید `q` را بزنید. در صورت وجود ساخت فعّال، ابتدا پنجرهٔ تأیید ظاهر میشود.

## 2. خلاصه و هدف پروژه

برنامه VoidForge برای کسانی ساخته شده است که میخواهند در Void Linux بسته بسازند، ولی نمیخواهند تمام مراحل را فقط با حفظ کردن دستورات پراکنده انجام دهند. این برنامه تلاش نمیکند جای `xbps` یا `xbps-src` را بگیرد؛ بلکه یک رابط کاربری واقعی روی همان ابزارهای رسمی Void است.

### اهداف اصلی

- اتصال به یک درخت واقعی `void-packages`
- خواندن و ویرایش الگوهای `srcpkgs/<name>/template`
- بررسی وابستگیها و تشخیص چرخههای احتمالی
- ساخت و ویرایش پچها با پشتیبانگیری از فایلهای تغییر یافته
- اجرای فازهای رسمی `xbps-src` با لاگ زنده
- تحلیل لاگ خطا بر اساس شواهد موجود در همان لاگ
- مشاهده و مدیریت تغییرات Git و عملیات remote
- فهرست کردن بستههای ساختهشده در `hostdir/binpkgs`
- ذخیرهٔ تنظیمات و تاریخچه در SQLite محلی

### اصل مهم

هیچ عدد، نمودار، بسته، لاگ یا وضعیت ساخت ساختگی وجود ندارد. هر چیزی که در رابط دیده میشود یا
از فایل سیستم خوانده شده، یا از یک فرآیند واقعی `git` / `xbps-src` / `curl` / `xbps-query` آمده است.

## 3. چرا رابط گرافیکی کنار گذاشته شد؟

نسخهٔ نخستین پروژه بر پایهٔ Tauri، React و TypeScript ساخته شد و مرحلهٔ بنیاد آن کاملاً تست شده بود،
اما هنگام اجرای واقعی پنجرهای نمایش داده نمیشد و تنها خطایی مربوط به localhost دیده میشد. بهجای
اضافه کردن لایههای مختلف و عیب زدایی وبvie، تصمیم گرفته شد همان پروژه بهطور کامل به یک TUI بومی Rust تبدیل شود.

### آنچه حذف شد

- `src-tauri`
- `src` قدیم مربوط به React و TypeScript
- `dist`
- `node_modules`
- `package.json`
- `package-lock.json`
- `vite.config.ts`
- `tsconfig.json`
- `index.html`

### آنچه ساخته شد

- باینری مستقل `voidforge`
- رابط ترمینالی با ratatui و crossterm
- بکاند کاملاً Rust و بدون سرور
- SQLite با مهاجرت خودکار دیتابیس
- سیستم رویدادها و لاگ زنده
- ۱۰ صفحهٔ کاملاً کاربردی

نتیجه: اجرا فقط به یک ترمینال نیاز دارد و هیچ ارتباطی با مرورگر، وبسرور یا DISPLAY ندارد.

## 4. پیشنیازها

### الزامی

- Void Linux x86_64 با glibc
- Rust و Cargo نسخهٔ `1.89` یا بالاتر
- یک ترمینال واقعی با پشتیبانی از حالت raw و رنگ
- یک درخت `void-packages` معتبر

### ابزارهایی که VoidForge تشخیص میدهد

| ابزار | کار |
|---|---|
| `xbps-src` | اجرای فازهای رسمی ساخت بسته |
| `xbps` | سیستم بستههای Void |
| `xbps-query` | خواندن metadata بستهها |
| `xbps-rindex` | ایجاد و بروزرسانی ایندکس مخزن محلی |
| `git` | وضعیت، diff، stage، commit و remote |
| `patch` | اعمال و بازگردانی پچها |
| `curl` | دانلود منابع و تماس با GitHub API |
| `tar` | استخراج آرشیوها |
| `bash` | اجرای اسکریپتهای Void |
| `ninja` | ابزار ساخت برخی پروژهها |

نصب نمونه در Void:

```bash
sudo xbps-install -S rust git curl tar bash patch ninja xbps xbps-src
```

VoidForge هرگز با `sudo` اجرا نمیشود و عملیات ساخت را بهصورت unprivileged انجام میدهد.

## 5. آموزش گامبهگام شروع کار

### گام ۱: وارد پروژه شوید

```bash
cd ~/VoidForge
```

### گام ۲: برنامه را اجرا کنید

```bash
cargo run
```

در اولین اجرا، صفحهٔ Dashboard نشان میدهد که هنوز workspaceای ثبت نشده است.

### گام ۳: یک درخت `void-packages` معرفی کنید

اگر از قبل در مسیر `~/void-packages` دارید:

```bash
:workspace add ~/void-packages
```

در داخل برنامه کلید `:` را بزنید، دستور را تایپ کنید و Enter بفشارید.

اگر هنوز مخزن را کلون نکردهاید:

```bash
:workspace clone https://github.com/void-linux/void-packages.git
```

سپس:

```bash
:workspace validate
```

صفحهٔ Diagnostics نشان میدهد که آیا پوشههای لازم مانند `srcpkgs`، `common`، `xbps-src` و `.git`
وجود دارند یا خیر.

### گام ۴: فهرست بستهها را ببینید

با کلید `3` وارد صفحهٔ Packages شوید. برنامه تمام الگوهای موجود در `srcpkgs` را میخواند.
برای فیلتر کردن:

```bash
/foo
```

### گام ۵: یک بستهٔ تازه بسازید

```bash
:pkg new mypackage
```

سپس بسته را باز کنید:

```bash
:pkg open mypackage
```

و با کلید `e` الگوی آن را در ویرایشگر دلخواه باز کنید.

### گام ۶: الگو را بررسی کنید

```bash
:template validate
```

یا کلید `v` را بزنید. نتایج شامل متغیرهای ضروری، شمارهٔ خطوط و شواهد مربوط به الگو است.

### گام ۷: ساخت بسته

وارد صفحهٔ Build Center شوید:

```bash
:view build
```

فاز موردنظر را با `j` / `k` انتخاب کنید و Enter بزنید. فرمان معادل:

```bash
:build pkg mypackage
```

## 9. گردش کار ساخت یک بسته

یک چرخهٔ معمولی ساخت بسته در VoidForge به شکل زیر است:

### ۱. اتصال به مخزن

```bash
:workspace add ~/void-packages
:workspace validate
```

### ۲. ایجاد یا انتخاب بسته

```bash
:pkg new hello-world
:pkg open hello-world
```

### ۳. ویرایش الگو

با کلید `e`، الگو در ویرایشگر مشخصشده در `$EDITOR` باز میشود. مقدار پیشفرض `vi` است و قابل تغییر است:

```bash
:editor nano
```

پس از بسته شدن ویرایشگر، VoidForge الگو را دوباره میخواند.

### ۴. بررسی الگو

```bash
:template validate
```

مواردی مانند `pkgname`، `version`، `homepage`، `distfiles`، `checksum` و `build_style` بررسی میشوند.

### ۵. بررسی وابستگیها

```bash
:deps cycles
```

این فرمان چرخههای احتمالی میان بستهها را تحلیل میکند و نتیجه را در صفحهٔ Diagnostics نشان میدهد.

### ۶. بررسی منبع

```bash
:source verify
:source download
:source extract
```

/checksumها با فایلهای موجود در `hostdir/sources` مقایسه میشوند.

### ۷. ساخت

```bash
:build pkg hello-world
```

یا از صفحهٔ Build Center فاز `pkg` را انتخاب و Enter بزنید. لاگ بهصورت زنده نمایش داده میشود و در
مسیر `~/.local/share/voidforge/logs/` ذخیره میگردد.

### ۸. تشخیص در صورت شکست

```bash
:diagnose last
```

برنامه لاگ ذخيرهشده را تحلیل میکند و شواهد واقعی مانند خطاهای دانلود، checksum، کامپایل، پچ و
وابستگی را نشان میدهد.

### ۹. مشاهده خروجی

```bash
:release list
```

فایلهای `.xbps` موجود در `hostdir/binpkgs` فهرست میشوند. نام بسته، نسخه، اندازه و مسیر واقعی آنها
نمایش داده میشود.

## 10. تشخیص خطا و خواندن لاگ

صفحهٔ Diagnostics تنها زمانی پر میشود که شواهد واقعی وجود داشته باشد. منابع آن عبارتند از:

- اعتبارسنجی ساختار `void-packages`
- اعتبارسنجی الگوی بسته
- تحلیل چرخهٔ وابستگیها
- تحلیل لاگ ساخت شکستخورده

هر نتیجه دارای موارد زیر است:

- severity: خطا، هشدار یا اطلاعات
- عنوان و توضیح
- شاهد متنی یا شماره خط
- مشخص بودن اینکه نتیجه «تأییدشده» است یا صرفاً پیشنهاد

مثال:

```bash
:build build hello-world
# در صورت شکست:
:diagnose last
```

لاگها ساختگی نیستند؛ مستقیم از stdout و stderr فرآیند `xbps-src` خوانده میشوند.

1. رابط کلید یا فرمان را میگیرد.
2. `app.rs` آن را به عملیات تبدیل میکند.
3. عملیاتهای بلندمدت در thread جداگانه اجرا میشوند.
4. خروجیها بهصورت `UiEvent` به رابط ارسال میشوند.
5. رابط بدون مسدود شدن، لاگ و وضعیت را بروزرسانی میکند.

## 13. ذخیرهسازی و ایمنی

### مسیرها

| نوع داده | مسیر |
|---|---|
| دیتابیس | `~/.local/share/voidforge/voidforge.sqlite3` |
| لاگها | `~/.local/share/voidforge/logs/` |
| جایگزین دیتابیس | `$XDG_DATA_HOME/voidforge/voidforge.sqlite3` |
| الگوها | `<workspace>/srcpkgs/<name>/template` |
| پچها | `<workspace>/srcpkgs/<name>/patches/` |
| بستههای خروجی | `<workspace>/hostdir/binpkgs/` |

### نکات ایمنی

- هرگونه عمل خطرناک دارای پنجرهٔ تأیید است:
  - حذف workspace از دیتابیس
  - تغییر نام بسته
  - حذف پچ
  - اعمال یا بازگردانی پچ
  - pull و push
  - ایندکس مخزن
  - `xbps-src clean`
  - خروج در هنگام ساخت فعّال
- مسیرها قبل از استفاده بررسی میشوند و اجازهٔ خروج از workspace داده نمیشود (حتی اگر از طریق پیوند نمادین باشد).
- فرمانها بدون shell اجرا میشوند تا تزریق فرمان رخ ندهد.
- فایلها تنها زمانی تغییر میکنند که کاربر صراحتاً فرمان مربوطه را اجرا کند.
- در نسخهٔ فعلی، دیتابیسهای قدیمی که فاقد ستون `remotes` بودند بهصورت خودکار ارتقا مییابند.

## 14. گزارش تست و تأیید نهایی

پس از تبدیل کامل پروژه به TUI، موارد زیر اجرا و تأیید شد:

```bash
cargo fmt --all
cargo check --all-targets
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo build
```

### نتیجه

| بررسی | نتیجه |
|---|---|
| `cargo fmt` | موفق |
| `cargo check --all-targets` | بدون خطا |
| `cargo test --all-targets` | ۲۵ تست (۲۰ واحد + ۵ یکپارچگی)، همگی موفق |
| `cargo clippy -- -D warnings` | بدون هشدار |
| `cargo build` | باینری ساخته شد |
| اجرای تستی در pseudo-terminal | Dashboard و Packages با اطلاعات واقعی رندر شدند |
| `:deps cycles` با ~۱۵٬۰۰۰ الگو | کامل و بدون گیر کردن اجرا شد |
| `:release list` و خروج `q` | پاسخ دادند |
| وابستگی به localhost | وجود ندارد |
| وابستگی به GUI/WebKit | وجود ندارد |

در تست نهایی، مواردی مانند عنوان `VoidForge — Dashboard`، اطلاعات `Void Linux`، کرنل، معماری،
وضعیت ابزارها، CPU، حافظه، swap و نوار فرمان بهدرستی نمایش داده شدند.

## 15. عیبزدایی

### خطا: `not a terminal` یا رفتار عجیب در هنگام اجرا

TUI نیاز به یک ترمینال واقعی دارد. برنامه را در یک shell معمولی اجرا کنید، نه در یک خط لوری که فاقد TTY است.

```bash
cd ~/VoidForge
cargo run
```

### خطا: `xbps-src not found`

یعنی workspace معرفیشده معتبر نیست یا مسیر آن درست انتخاب نشده است:

```bash
:workspace validate
```

سپس مسیر صحیح را ثبت کنید:

```bash
:workspace add ~/void-packages
```

### ابزارها بهصورت `--` نمایش داده میشوند

این وضعیت بهمعنای پیدا نشدن ابزار در `PATH` یا workspace است. ابزار لازم را نصب کنید و دوباره:

```bash
r
```

را بزنید.

### خطای مربوط به دیتابیس قدیمی

اگر دیتابیس قدیمی فاقد ستون `remotes` باشد، VoidForge بهصورت خودکار آن را اضافه میکند. نیازی به
حذف دستی دیتابیس نیست.

### ساخت متوقف نشد

از صفحهٔ Build Center کلید `x` را بزنید یا:

```bash
:build cancel
```

در صورت نیاز، فرآیند بهصورت process group متوقف میشود تا فرزندان `xbps-src` هم باقی نمانند.

### ویرایشگر باز نشد

ویرایشگر پیشفرض `vi` است. مقدار دلخواه را تنظیم کنید:

```bash
:editor nano
```

یا:

```bash
:editor "code --wait"
```

cd ~/VoidForge && cargo run
