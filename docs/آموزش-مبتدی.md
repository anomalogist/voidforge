# VoidForge — آموزش صفر تا صد برای مبتدی

**نسخه:** `1.0.0` (انتشار پایدار) · **لایسنس:** MIT

این راهنما برای کسی نوشته شده که **هیچ تجربهای با ابزارهای خط فرمان Void Linux ندارد**.
همه چیز را از لحظهای که ترمینال را باز میکنید تا ساخت اولین بسته قدمبهقدم پیش میبریم.

> نکتهٔ مهم: VoidForge جای ابزار رسمی Void یعنی `xbps-src` را نمیگیرد. فقط یک «تابلو کنترل» در ترمینال است
> که همان ابزار رسمی را برایتان اجرا میکند و نتیجهاش را نمایش میدهد. پس نگران نباشید؛ چیز جادوییای اتفاق
> نمیافتد، فقط کارها مرتبتر میشوند.

## 1. VoidForge دقیقاً چیست؟

تصور کنید برای ساخت یک بستهٔ Void Linux معمولاً باید دستورات زیادی را حفظ باشید:
از کجا الگو را پیدا کنم، چطور `xbps-src` را اجرا کنم، لاگ خطا را کجا بخوانم،
تغییرات Git را چطور ثبت کنم و … .

VoidForge همهٔ اینها را در **یک پنجرهٔ متنی** گردآوری میکند:

- بالای صفحه: مشخصات سیستم و وضعیت بستهٔ در حال ساخت
- سمت چپ: ۱۰ صفحه که با کلیدهای `1` تا `0` جابهجا میشوید
- وسط: محتوای صفحهای که انتخاب کردهاید
- پایین: پیامها و محل تایپ دستورها

**هیچ مرورگر، سرور وب، یا رابط گرافیکی در کار نیست.** فقط همان ترمینالی که جلوی شماست.

## 2. پیش از شروع: سه چیز که باید بدانید

### الف) نباید از `sudo` استفاده کنید

ساخت بسته در Void Linux بهصورت کاربر عادی انجام میشود. اگر برنامه را با `sudo` اجرا کنید،
فایلها با مالکیت اشتباه ساخته میشوند و بعداً `xbps-src` شکست میخورد.

پس همیشه:

```bash
cargo run
```

و هرگز این کار را نکنید:

```bash
sudo cargo run   # ❌ اشتباه
```

### ب) `~` یعنی «پوشهٔ خانهٔ من»

وقتی مینویسید `~/void-packages` یعنی پوشهٔ `void-packages` داخل پوشهٔ خانهٔ شما (مثلاً `/home/username/void-packages`).
خود برنامه این مخفف را میفهمد، پس لازم نیست مسیر کامل را تایپ کنید.

### ج) ماوس کار نمیکند

VoidForge یک برنامهٔ تماماً صفحهکلیدی است. فقط از کلیدها استفاده کنید.

## 3. روش روشن کردن برنامه

### گام ۰: اگر برنامه را هنوز نصب نکردهاید

```bash
git clone <آدرس-مخزن-شما> ~/VoidForge
cd ~/VoidForge
cargo build --release
```

سپس باینری آماده در `target/release/voidforge` است. میتوانید آن را با `./target/release/voidforge`
اجرا کنید یا (اختیاری) با `sudo install -Dm755 target/release/voidforge /usr/local/bin/voidforge`
دستور `voidforge` را در سراسر سیستم دردسترس بگذارید. توجه: `sudo` فقط برای نصب باینری است، نه برای اجرای برنامه.

### گام ۱: ترمینال را باز کنید

معمولاً با `Ctrl+Alt+T` یا از منوی برنامهها. سپس وارد پوشهٔ پروژه شوید:

```bash
cd ~/VoidForge
```

### گام ۲: برنامه را اجرا کنید

```bash
cargo run
```

**اولین بار** ممکن است یک تا دو دقیقه طول بکشد چون Rust باید کدها را کامپایل کند.
دفعات بعدی تقریباً بلافاصله باز میشود. وقتی صفحهای شبیه تصویر زیر دیدید، یعنی برنامه روشن شده است:

```text
 VoidForge — Dashboard — no workspace — idle
┌ VoidForge ────┐ ┌ Host ──────────────┐ ┌ CPU ─────────┐
│ 1 Dashboard   │ │OS       Void Linux  │ │ 13.6%        │
│ 2 Workspaces  │ │Kernel   6.18.64_1   │ └──────────────┘
│ 3 Packages    │ │Workspace none       │ ...
└───────────────┘ └────────────────────┘
: help   / filter   ? keys   q quit   Tab screens
```

### گام ۳ (اختیاری): نسخهٔ سریعتر

اگر میخواهید هر بار بدون کامپایل کردن اجرا شود، یک بار بسازید:

```bash
cargo build --release
./target/release/voidforge
```

### خارج شدن

برای بستن برنامه کلید `q` را بزنید. اگر بستی در حال اجرا باشد، ابتدا پنجرهٔ تأیید میآید
و با زدن `Enter` بست متوقف و برنامه بسته میشود. `Ctrl+C` هم همین کار را میکند.

## 4. آشنایی با صفحهای که میبینید

سه قسمت اصلی:

| قسمت | محل | کار |
|---|---|---|
| نوار عنوان | بالاترین خط | نام صفحه، نام مخزن، وضعیت بست |
| منو | سمت چپ | ۱۰ صفحه با شمارههای `1` تا `0` |
| محتوا | وسط | اطلاعات صفحهای که انتخاب کردهاید |
| نوار پیام | پایینترین خطوط | نتیجهٔ آخرین دستور + خط فرمان |

**خط فرمان داخلی** جایی است که دستورهایی مثل `:workspace add ...` مینویسید:

1. کلید `:` را بزنید.
2. بقیهٔ دستور را تایپ کنید (دوباره کولون نزنید).
3. `Enter` بفشارید.

مثال: بعد از زدن `:`، بنویسید `workspace validate` و Enter بزنید.
در واقع دستور کامل `:workspace validate` میشود.

اگر اشتباه تایپ کردید، `Esc` خط فرمان را میبندد.

برای دیدن تمام کلیدها داخل برنامه `?` را بزنید.

## 5. اولین کار: معرفی کردن مخزن بستهها

منظور از «مخزن» همان پوشهٔ `void-packages` است که شامل الگوها و اسکریپت ساخت رسمی Void است.
اگر از قبل مخزن `void-packages` را در پوشهٔ خانهٔ خود دارید (`~/void-packages`) و در صفحهٔ `2`
(Workspaces) آن را دیدید، نیازی به معرفی دوباره نیست. در غیر این صورت مراحل زیر را دنبال کنید.

اگر لیست خالی بود، این کارها را کنید:

### گام ۱: وارد صفحهٔ Workspaces شوید

کلید `2` را بزنید.

### گام ۲: دستور معرفی را بدهید

`:` بزنید، سپس بنویسید:

```text
workspace add ~/void-packages
```

و Enter بفشارید. چند ثانیه صبر کنید ( برنامه در حال خواندن هزاران الگو است).

### گام ۳: بررسی کنید که مخزن سالم است

با کلید `8` به صفحهٔ Diagnostics بروید. در صفحهٔ Workspaces هم در ستون Valid باید `true` دیده شود.
اگر لازم بود دستور `:workspace validate` را هم اجرا کنید.

> معنی پیغامهای صفحهٔ Diagnostics:
> `[E]` خطا، `[W]` هشدار، `[I]` اطلاعات. Enter روی هر مورد، متن شاهد آن را نشان میدهد.

## 6. دومین کار: دیدن لیست بستهها

1. کلید `3` را بزنید (صفحهٔ Packages).
2. حدود ۹٬۷۰۰ پوشه و ۱۵٬۰۰۰ الگو از پوشهٔ `srcpkgs` خوانده میشود (اسکن آن معمولاً چند ثانیه طول میکشد).
3. برای جابهجایی در لیست از `j` (پایین) و `k` (بالا) یا کلیدهای جهتدار استفاده کنید.
4. برای فیلتر کردن، کلید `/` را بزنید و مثلاً `hello` تایپ کنید و Enter بفشارید.
5. با `Enter` روی بستهٔ انتخابشده، وارد صفحهٔ الگو میشوید.

در سمت راست صفحه، مشخصات بستهٔ انتخابشده (نام، نسخه، مسیر) نمایش داده میشود.

**پیشنهاد برای اولین تمرین:** بستهٔ `hello` را انتخاب کنید. یک بستهٔ کوچک رسمی Void است و الگوی سادهای دارد.

## 7. سومین کار: ساخت یک بستهٔ تازه

دو راه دارید:

### الف) از روی یک بستهٔ موجود (پیشنهادی)

```text
:pkg duplicate hello my-first-package
:pkg open my-first-package
:editor nano
e
```

دستور آخر (`e`) الگو را در ویرایشگر باز میکند. بعد از ذخیره و بستن ویرایشگر،
برنامه 자동 الگو را دوباره میخواند.

> دقت کنید: `duplicate` تمام محتویات پوشه را کپی میکند و در الگوی کپیشده `pkgname` را عوض مینماید.
> شما باید `version`، `short_desc`، `distfiles` و `checksum` را هم متناسب با بستهٔ خود تغییر دهید.

### ب) از صفر

```text
:pkg new my-first-package
:pkg open my-first-package
:editor nano
e
```

الگوی ایجادشده فقط یک «قالب خالی» است و حتماً باید پر شود؛ در غیر این صورت اعتبارسنجی خطا میدهد.

## 8. چهارمین کار: بررسی الگو

وقتی بستهٔ موردنظر باز است:

- کلید `v` را بزنید، یا
- دستور `:template validate` را اجرا کنید.

سپس با `8` به Diagnostics بروید. برنامه مواردی مانند:

- وجود `pkgname`, `version`, `revision`, `short_desc`, `maintainer`, `license`, `homepage`
- درست بودن `checksum` (باید ۳۶ کاراکتر هگزادسیمال / SHA256 باشد)
- تکراری بودن وابستگیها
- وجود `distfiles`

را بررسی میکند و شمارهٔ خط مربوطه را هم نشان میدهد.

**توجه:** اینها بررسی «ایستا» هستند. یعنی تضمین نمیکنند بسته حتماً ساخت شود؛ فقط جلوی اشتباههای رایج را میگیرند.

## 9. پنجمین کار: ساخت بسته با xbps-src

### گام ۱: به Build Center بروید

کلید `7` را بزنید. در سمت چپ لیست فازها را میبینید:

```text
bootstrap
binary-bootstrap
fetch
extract
patch
configure
build
check
install
pkg
clean
```

فاز `pkg` تمام مراحل را تا تولید بستهٔ نهایی انجام میدهد. برای شروع معمولاً همان را انتخاب کنید.

### گام ۲: بسته و فاز را مشخص کنید

- با `j` / `k` فاز را انتخاب کنید.
- مطمئن شوید بستهٔ دلخواه در صفحهٔ Packages انتخاب شده است.
- `Enter` یا کلید `b` را بزنید.

معادل دستوری آن:

```text
:build pkg hello
```

### گام ۳: لاگ زنده را تماشا کنید

در قسمت Logs خروجی واقعی `xbps-src` خط به خط ظاهر میشود.
برای متوقف کردن بست، `x` یا `:build cancel` را بزنید.

### گام ۴: فاز `clean`

اگر `clean` را انتخاب کنید، پنجرهٔ تأیید ظاهر میشود چون فایلهای ساخت پاک میشوند.
`Enter` تأیید و `Esc` لغو است.

## 10. اگر ساخت شکست خورد

وقتی بست شکست بخورد، برنامه بهطور خودکار به صفحهٔ Diagnostics میرود.
همچنین میتوانید دستور زیر را بزنید:

```text
:diagnose last
```

 برنامه لاگ ذخیرهشده را تحلیل کرده و الگوهای خطای شناختهشدهای را پیدا میکند:

- خطای وابستگی
- خطای CMake / configure
- خطای کامپایلر یا لینکر
- شکست پچ
- عدم تطابق checksum
- خطای دسترسی یا فایل گمشده

برای هر مورد، متن دقیق خطا از لاگ واقعی بهعنوان «شاهد» نشان داده میشود.
همچنین ۱۲ خط آخر لاگ در انتهای لیست اضافه میشود تا ببینید درست قبل از شکست چه اتفاقی افتاد.

لاگها در این مسیر ذخیره میشوند:

```text
~/.local/share/voidforge/logs/
```

## 11. دیدن بستهٔ ساختهشده

دستور:

```text
:release list
```

در صفحهٔ Build Center، قسمت **Built packages** فهرست فایلهای `.xbps` موجود در
`hostdir/binpkgs` را نشان میدهد: نام، نسخه و حجم واقعی.

برای جزئیات یک بسته:

```text
:release info hello
```

 این اطلاعات را با `xbps-query` از مخزن محلی میخواند.

برای بروزرسانی ایندکس مخزن محلی:

```text
:release index
```

(با تأیید همراه است چون `xbps-rindex -a` فایل ایندکس را تغییر میدهد.)

## 12. ذخیره کردن تغییرات با Git

الگوها داخل یک مخزن Git واقعی هستند. گردش کار ساده:

```text
:git status              # ببینم چه چیزی تغییر کرده
:git diff                # تفاوتها را ببینم
:git stage srcpkgs/my-first-package/template
:git commit "my-first-package: initial template"
```

برای کار با مخزن از راه دور:

```text
:git fetch origin
:git pull origin master
:git push origin master
```

`pull` و `push` حتماً پنجرهٔ تأیید دارند، چون محیط خارجی را عوض میکنند.
در صورت لغو، هیچ کاری انجام نمیشود.

## 13. تمام کلیدها در یک جدول

| کلید | کار |
|---|---|
| `1` … `0` | پرش مستقیم به صفحه (صفحهٔ ۰ همان Settings است) |
| `Tab` / `Shift+Tab` | صفحهٔ بعدی / قبلی |
| `j` / `↓` | حرکت به پایین |
| `k` / `↑` | حرکت به بالا |
| `Home` / `End` | ابتدا / انتهای لیست |
| `Enter` | فعّال کردن گزینهٔ انتخابشده |
| `e` | باز کردن الگو در ویرایشگر (در صفحهٔ Packages یا Template) |
| `v` | بررسی الگو |
| `b` | شروع ساخت بستهٔ انتخابشده با فاز فعلی |
| `x` | لغو بست فعّال |
| `r` | تازهسازی اطلاعات مخزن |
| `t` | تغییر تم (فقط در صفحهٔ Settings) |
| `:` | باز کردن خط فرمان داخلی |
| `/` | فیلتر سریع بستهها |
| `?` | نمایش / بستن راهنما |
| `Esc` | بستن راهنما، پیام یا خط فرمان |
| `q` | خروج (با تأیید در صورت وجود بست فعّال) |
| `Ctrl+C` | خروج ایمن همانند `q` |

## 14. رفع مشکلات رایج

### «خطای not a terminal» یا رفتار عجیب

یعنی برنامه را داخل محیطی اجرا کردهاید که ترمینال واقعی نیست (مثلاً برخی ویرایشگرهای آنلاین).
باید یک ترمینال معمولی باز کنید و همان دستور `cargo run` را داخل آن بزنید.

### ابزارها بهصورت `--` نمایش داده میشوند

یعنی ابزاری مثل `ninja` یا `patch` نصب نیست. نصب نمونه در Void:

```bash
sudo xbps-install -S rust git curl tar bash patch ninja xbps xbps-src
```

سپس داخل برنامه `r` بزنید.

### پیامی دیدید که دوباره نمیشود

با `:clear` یا `Esc` پاک میشود (پیامها فقط در نوار پایین هستند).

### برنامه کند شده بود

در نسخهٔ فعلی این مشکل برطرف شده است: جابهجایی در لیست بستهها دیگر مخزن Git را دوباره اسکن نمیکند.
اگر باز هم خارج از انتظار کند بود، `q` بزنید و دوباره اجرا کنید.

### ویرایشگر باز نشد

پیشفرض `vi` است. میتوانید تغییر دهید:

```text
:editor nano
```

یا:

```text
:editor "code --wait"
```

### دیتابیس قدیمی

اگر نسخهٔ قدیمیای از برنامه داشته باشید، ستونهایใหม่ بهصورت خودکار اضافه میشوند و نیازی به پاک کردن دستی دیتابیس نیست.

## 15. چیتشیت ۵ دقیقهای

```bash
# ۱) اجرا
cd ~/VoidForge && cargo run
```
